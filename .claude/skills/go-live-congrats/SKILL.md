Guides the user step-by-step: asks for project name, QA names, Slack channel(s), tone, and a go-live email or image — then composes, previews (with edit/regenerate loop), resolves @mentions, and posts to one or more channels. Use when asked to congratulate the team on a go-live, launch, release, or successful deployment. Tip: for a form-based experience, open go-live-congrats.html in a browser instead.
argument-hint: (no args needed — skill will ask you each question)

## Fast Mode — HTML Form Integration

**If the skill is invoked with `--channel` and `--message` arguments** (generated by the "Send via Claude" button in `go-live-congrats.html`), skip all collection steps and post directly to Slack.

### Detecting fast mode

Check whether the input args contain both `--channel` and `--message`. Example input:
```
/go-live-congrats --channel "#it-prodops-qa" --message "BASE64ENCODEDTEXT"
```

### Fast mode steps

1. **Parse args:**
   - Extract `--channel` value → `CHANNEL`
   - Extract `--message` value → `BASE64_MSG`

2. **Decode the message** using Bash:
   ```
   echo "<BASE64_MSG>" | base64 --decode
   ```
   The output is the plain Slack `mrkdwn` message text.

3. **Post to Slack immediately** — call `mcp__slack__post_message` with:
   - `channel`: CHANNEL (strip leading `#` if needed)
   - `text`: the decoded message

4. **Confirm** with one line:
   ```
   ✅ Posted to CHANNEL
   ```

**CRITICAL — NO PROMPTS, NO APPROVAL, NO PREVIEW:**
- Do NOT show the decoded message before posting
- Do NOT ask "Does this look good?" or any confirmation question
- Do NOT ask for approval to call `mcp__slack__post_message`
- Do NOT show a preview or draft
- The user already approved this message in the HTML form — post it immediately and report done
- The entire fast mode should complete in a single turn: decode → post → confirm ✅

## Interaction Mode — Guided Step-by-Step

**If no `--channel` / `--message` args are present:** collect inputs by asking the user one question at a time in this exact order. Wait for each answer before asking the next.

---

## Collection Steps (ask in order, one at a time)

### Question 1 — Project Name

Ask:
> What is the project name?

Wait for the user's reply. Store as `PROJECT_NAME`.

---

### Question 2 — QA Names

Ask:
> Who are the QA team members to recognize? (Enter names or Slack handles, e.g. Alice, @bob, Carol — or type "skip" to leave this out)

Wait for the user's reply.
- If they provide names → store as `QA_NAMES` (list)
- If they type "skip" or leave blank → set `QA_NAMES = null`

**@mention resolution (if `QA_NAMES` is set):**

For each entry in `QA_NAMES`, attempt to resolve to a Slack user ID:
- If the entry already looks like a raw user ID (e.g. `U012AB34C`) → format as `<@U012AB34C>`
- Otherwise → call `mcp__slack__search_messages` with `query = "from:@<name>"` and `count = 1`
  - If a result is returned → extract the `user` field from the first message → format as `<@USERID>`
  - If no result is returned → keep as plain text name

Store the resolved list as `QA_MENTIONS` (mix of `<@USERID>` and plain name strings as needed).

---

### Question 3 — Slack Channel(s)

Ask:
> Which Slack channel(s) should I post to? (Separate multiple channels with commas, e.g. #qa-team, #general)

Wait for the user's reply. Split by comma and trim whitespace. Store as `SLACK_CHANNELS` (list).

---

### Question 4 — Go-Live Email or Image

Ask:
> Please share the go-live announcement — paste the email text, or provide a path to a screenshot image. (Or type "skip")

Wait for the user's reply.
- If they paste text → store as `ANNOUNCEMENT_TEXT`, set `SOURCE = "email text"`
- If they provide a file path ending in `.png`, `.jpg`, `.jpeg`, or `.webp` → use the `Read` tool to load the image and extract the content, set `SOURCE = "image"`
- If they type "skip" → set `ANNOUNCEMENT_TEXT = null`, `SOURCE = "none"`

**From the email text or image, extract:**
- `EXTRACTED_DESCRIPTION` — the body paragraph(s) describing what was built, what it replaces/improves, which systems or markets are affected
- `EXTRACTED_STATUS` — the status label if present (e.g. "Live in Production", "Successfully Deployed")

---

### Question 5 — Tone

Ask:
> What tone would you like for the message?
>
> 1. **Professional** — polished, measured, workplace-appropriate
> 2. **Casual** — friendly, relaxed, conversational
> 3. **Celebratory** — high-energy, enthusiastic, emoji-rich

Wait for the user's reply (accept "1"/"2"/"3" or the word). Store as `TONE`.

---

## Compose, Preview, and Post

Once all 5 answers are collected, proceed automatically.

---

### STEP A — Compose the Slack message

Write a **fresh, unique message** using the collected inputs. Apply tone rules:

- **Professional:** measured language, clear structure, no excessive exclamation marks. Use 🚀 in the headline only. No filler phrases.
- **Casual:** conversational, contractions OK, light warmth. Use 2–3 emoji naturally throughout.
- **Celebratory:** enthusiastic and punchy. Use 3–5 emoji including in the shoutout section (e.g. 🎉, 🙌, ⭐).

Rules that apply to **all** tones:
- Slack `mrkdwn` formatting: `*bold*`, `_italic_`, `•` bullets.
- Open with a bold headline: `🚀 *<PROJECT_NAME> — <EXTRACTED_STATUS or "Live in Production">!*`

**Project scope — keep it brief (max 6 lines total):**
- One sentence describing what was built and what it replaces/improves.
- Then `*What shipped:*` followed by **at most 3** tight bullet points (key capabilities only, no exhaustive feature list).
- If announcement content was provided, pull the most impactful 1–3 points from it — do not paste a wall of text.
- If no announcement content was provided, write one short general sentence and omit the bullet list.

**QA spotlight — the most prominent section of the message:**
- This section **must appear last** before the closing line and be visually separated with `---` dividers above and below.
- Open with a strong, attention-grabbing header: `⭐ *Spotlight: The QA Team Behind This Launch* ⭐`
- Write **5–7 rich sentences** from the QA Lead's perspective, weaving in ALL of these dimensions naturally (not as a bullet list):
  - **Functional testing** — validating every feature end-to-end before production
  - **Defect discovery** — the sharp eye for catching bugs, edge cases, and integration gaps before users saw them
  - **Defect retesting & verification** — confirming every fix was solid, not just patched
  - **Regression testing** — ensuring new changes didn't break existing functionality across the full system
  - **Quality gates** — holding the bar and refusing to let anything through that wasn't production-ready
  - **Timeline discipline** — delivering thorough coverage without compromising the go-live date
  - **Cross-platform / cross-scenario coverage** — validating across environments, marketplaces, or workflows
- After those sentences, add a **personal, heartfelt closing line** of gratitude (_italicized_) — specific and genuine, not generic ("thank you for your hard work" is not enough).
- Then list team members with a 🌟 bullet using `QA_MENTIONS`, formatted as bold with `@` prefix:
  ```
  *A huge shoutout and congratulations to:*
  • 🌟 *<@U123>* (if resolved to Slack ID)
  • 🌟 *@Plain Name* (if unresolved — always bold + @ prefix, e.g. *@Bhavani Marupaka*)
  ```
  **IMPORTANT:** QA names must ALWAYS appear as `*@Name*` — bold + `@` symbol. Never plain text.
- The QA section should be the emotional center of the message — it should feel like a genuine, meaningful recognition, not a footnote or afterthought.
- If `QA_NAMES` is null → omit the spotlight section entirely.

Keep the full message under 30 lines.

---

### STEP B — Preview and Confirm

Show the composed message inside a clearly labelled block so the user sees exactly what will be posted:

```
Here's the draft message:

────────────────────────────────
<composed message here>
────────────────────────────────

Does this look good?
• Reply *yes* to post it
• Reply *edit* to describe what you'd like changed
• Reply *regenerate* for a completely fresh draft
```

Wait for the user's reply:
- **"yes"** → proceed to STEP C
- **"edit"** → ask: _"What would you like to change?"_ → apply their feedback to the existing draft → recompose → show STEP B again (loop)
- **"regenerate"** → compose a brand-new draft with different phrasing and structure → show STEP B again (loop)

Continue looping STEP B until the user replies "yes".

---

### STEP C — Post to Channel(s)

For each channel in `SLACK_CHANNELS`:
- Call `mcp__slack__post_message` with:
  - `channel`: the current channel
  - `text`: the approved message

If a post fails, record the error and continue posting to the remaining channels.

---

### STEP D — Confirm

After all posts complete, respond with:

```
✅ Congratulations message posted!

📣 Channels:  <<SLACK_CHANNELS joined by ", ">>
🏆 Project:   <<PROJECT_NAME>>
👥 QA Team:   <<QA_NAMES joined by ", " — or "not specified">>
🎯 Tone:      <<TONE>>
📋 Source:    <<SOURCE>>
```

If any channel failed, list it separately with the error and suggest verifying the channel name.
